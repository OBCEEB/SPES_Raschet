## 0. Суть в двух предложениях

Минутные метки пиранометра в файлах `yymmdd.csv` по данным соответствуют **UTC**, а весь пайплайн читает их как **MSK (UTC+3)**: суточный ход GHI смещён на −165 мин относительно расчётного ясного неба, и при сдвиге меток на +3 ч смещение уходит до +15 мин. ## 3. Шаг 1 — исправить чтение меток в одном месте

Ввести единый модуль времени, например `scripts/lipetsk_time.py`:

```python
PYRANOMETER_FILE_TZ_H = 0.0   # шкала минуток yymmdd.csv (подтверждено в шаге 0)
ASMG_FILE_TZ_H = 0.0          # шкала c_YYYYMM.csv (подтверждено в шаге 0)
MSK_H = 3.0                   # гражданское время расчёта

def pyranometer_to_msk(t_file): return t_file + timedelta(hours=MSK_H - PYRANOMETER_FILE_TZ_H)
def asmg_to_msk(t_file):        return t_file + timedelta(hours=MSK_H - ASMG_FILE_TZ_H)
```

Применить **только при загрузке**, нигде больше:

| Файл | Функция | Что сделать |
|---|---|---|
| `lipetsk_q_vs_ngo.py` | `load_minutes`, `load_ngo` | минутки → `pyranometer_to_msk`; ASMG → `asmg_to_msk` |
| `lipetsk_collector.py` | `load_t_ssd`, `load_ngo` | то же |
| `lipetsk_ingest.py` | `load_sqlite`, `load_csv` | для sqlite/CSV, которые содержат исходные метки, — тот же перевод; для `hh_q_only.csv` после исправления метки уже MSK |
| `lipetsk_join_gaps.py`, `lipetsk_q_inventory.py` | загрузка минуток/ASMG | то же |
| `lipetsk_gti.py` | `omega_rad` | **не трогать** `MSK_H`: геометрия правильно считает MSK → истинное солнечное время |
| `lipetsk_actualize.py` | запись `hh_station.csv` | `timestamp_utc = obs_time_msk − 3 ч` станет верным автоматически |

Суточные границы — по MSK после перевода. Проверить, что сутки `yymm00.csv` (держат предыдущие сутки) после перевода не теряют/не дублируют записи.

Заменить на среднее всех минут интервала [t0, t0 + 30 мин) с порогом полноты (предложение: ≥ 24 из 30 минут; иначе слот пропущен) и записывать число минут в колонку `n_min`.
